# 安全の原則

産業制御は安全重視です。失敗は物理機器を動かすことがあります。その
ため安全性は最後に付け足されるのではなく、アーキテクチャに設計されて
います。

## 1. LLM は世界に直接触れない

モデルは計画者であり、アクチュエータではありません。モデルは作業を
依頼できますが、それを実行することはできません。モデルと機器の間には、
サンドボックス、ポリシーチェック、そして取り消し不能な操作のための
人間が介在します。モデルは、プラットフォームが公開するプリミティブの
外側で振る舞いを発明することはできません。

## 2. 多層の安全深度

物理世界に影響を与えうるすべての操作は、完全なチェーンを順に通過
します。

1. **指示レビュー** —— モデルが何をするよう指示されたか
2. **サンドボックス実行** —— コードはポリシー制約付きで分離実行される
3. **ポリシー検証** —— 書き込みゲート: 操作はポリシーに一致するか？
4. **人間の確認** —— 取り消し不能な操作に対する最終判断
5. **監査証跡** —— すべてが記録され、沈黙するものはない

どのレイヤも、その前のレイヤを信頼しません。1 つを飛ばすことは近道
ではなく欠陥です。

## 3. 混合クリティカリティ: リアルタイムは LLM に依存しない

システムは応答時間で分割され、**レイヤが高速であるほど、モデルの
オンライン状態への依存は小さくなります**:

| レイヤ | 何をするか | LLM 依存 |
| --- | --- | --- |
| 認知 | 計画、会話、オーケストレーション | 主な消費者 |
| 世界状態 | いま真であること（語られたことではない） | 任意 |
| 反応 | 機械そのものの上でのローカルな反応 | なし |
| リアルタイム制御 | インターロックと高速ループ | 決してない |

モデルがオフラインになっても、プラットフォームは優雅に劣化します。
安全状態になるか、承認済みの経路を実行し続けるかです。制御は決して
ネットワーク呼び出しを待ちません。

## 4. ゼロトラスト、フェイルクローズ

- 認証と認可は、エコシステムのゼロトラスト認証レイヤである
  [kirino](https://github.com/celestia-island/kirino) から得られます。
  ネットワークの内側にあるという理由で何かが信頼されることはありません。
- 登録はデフォルトで招待制。デプロイメントの最初のユーザーが管理者に
  なり、以降は自己登録がロックされます。
- 明示的に許可されていないものは拒否されます。サービスに *mock* モード
  がある場合、mock モードはデフォルトでオフになり、明示的なフラグなし
  では本番デプロイメントで動作を拒否します。

## 5. 失敗は明確に

静かな劣化は安全上のバグとして扱われます。メモリ呼び出しが失敗した、
バックエンドに到達できない、デプロイが失敗した —— その場合、API
レスポンスと UI は明示的に知らせなければなりません。偽の成功も、偽
データへのフォールバックもありません。この規則は、実インシデントが
示したこと —— 見えない失敗こそが危険な失敗である —— に基づいています。
