# 왜 celestia-island인가

celestia-island는 하나의 루프를 닫기 위해 존재합니다: **사용자가 플랫폼을
발견하는 순간부터 실제 산업 장비를 제어했음을 검증하는 순간까지 — 중간의
모든 것이 도구의 더미가 아니라 하나의 시스템으로 동작하는 것.**

## 문제

두 세계는 좀처럼 대화하지 않습니다:

- **AI 플랫폼**(채팅, 에이전트, 모델 배포)은 관대한 세계를 전제로 합니다:
  지연은 UX 문제일 뿐이고, 실패한 추론은 재시도되며, 물리적으로 움직이는
  것은 없습니다.
- **산업 제어**(프로토콜, 센서, 액추에이터)는 엄격한 세계를 전제로 합니다:
  데드라인, 인터록, 감사 추적, 그리고 소프트웨어 실패 시의 안전 상태가
  요구됩니다.

둘을 잇는다는 것은 SCADA 시스템에 챗봇을 덧붙이는 것을 거부하는 것을
의미합니다. 인증, 모델 배포, 에이전트 오케스트레이션, 프로토콜 브로커링,
감독까지의 전체 경로를 모든 단계에 안전 이야기가 있는 하나의 계층화된
시스템으로 설계하는 것을 의미합니다.

## 약속: 하나의 폐쇄 루프

루프가 제품입니다. 채팅 앱도, 제어 브로커도, 문서 사이트도 아닌 — **루프**
자체입니다:

> 발견 → 설치 → 인증 → 모델 배포 → 채팅 및 에이전트 실행 →
> 산업 장비 제어 → 검증 및 지원

모든 프로젝트는 이 루프의 한 구간을 신뢰할 수 있게 만드는 데 존재합니다.
루프가 어디서든 끊기면 플랫폼은 완성되지 않은 것입니다. [폐쇄 루프](./closed-loop.md)
페이지는 각 구간을 프로젝트에 연결합니다.

## 규율: 절대 두 번 구현하지 않기

저장소가 30개가 넘는 상황에서 질서는 하나의 규칙에서 나옵니다: **일반 기능은
상류에서 한 번 구축되고, 서비스는 비즈니스 로직만 구현합니다.** 인증
프리미티브는 [kirino](../ecosystem/projects.md)에서, 플랫폼 기능은
[plana](../ecosystem/projects.md)에서, UI 컴포넌트는 [hikari](../ecosystem/projects.md)에서
가져옵니다. 상류 기능을 다시 구현하는 서비스는 성과가 아니라 버그입니다.
전체 원칙은 [계층형 아키텍처](./layered-architecture.md)를 참조하세요.

## 지평: 로컬 자율성

지연은 운명입니다. 달에서는 신호 왕복에 2.6초가 걸리고, 화성에서는 6분에서
44분이 걸립니다. 그곳의 기계는 지구의 인간에게 의존할 수 없습니다 — 로컬에서
안전하고 예측 가능하게 결정을 내려야 합니다.

우리가 오늘 산업 제어를 위해 구축하는 형태 — 에이전트를 오케스트레이션하는
의사결정 계층, *지금* 무슨 일이 일어나고 있는지 아는 세계 모델, *아니요*라고
말할 수 있는 안전 게이트 — 는 달과 화성의 로봇이 필요로 할 것과 같은
형태입니다. 우리는 오늘 화성을 위해 구축하는 것이 아닙니다; 화성에 도달하는
시스템이 바로 이 시스템이 되도록 구축하고 있습니다. [내러티브와 지평](./narrative.md)을
참조하세요.
