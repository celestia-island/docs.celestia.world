# Принципы безопасности

Промышленное управление критично к безопасности: сбой может сдвинуть
физическое оборудование. Поэтому безопасность встроена в архитектуру, а не
добавлена поверх в конце.

## 1. LLM никогда не касается мира напрямую

В [entelecheia](https://github.com/celestia-island/entelecheia) модель видит
лишь небольшой набор примитивных инструментов (`exec`, `write_to_var`). Вся
реальная работа происходит внутри изолированного конвейера выполнения, где
код агента распределяет задачи по большому набору MCP-инструментов между
агентами. Модель не может выдумать поведение; она может только вызывать
примитивы, которые предоставляет платформа.

## 2. Многослойная глубина безопасности

Каждая операция, способная повлиять на физический мир, проходит всю цепочку,
по порядку:

1. **Проверка инструкций** — что модели было сказано сделать
2. **Изолированное выполнение** — код выполняется в изоляции, с ограничениями политик
3. **Проверка политик** — шлюз записи: соответствует ли операция политике?
4. **Подтверждение человеком** — последнее слово для необратимых действий
5. **Журнал аудита** — всё записывается, ничто не остаётся незамеченным

## 3. Смешанная критичность: реальное время никогда не зависит от LLM

Системы разделены по времени отклика, и **более быстрые слои никогда не
зависят от того, что модель онлайн**:

| Слой | Темп | Работает на | Зависимость от LLM |
| --- | --- | --- | --- |
| L3 — Познание | секунды–минуты | arona, shittim-chest, entelecheia (Linux) | основной потребитель |
| L2 — Модель мира | 10–50 Гц | платформенные сервисы | опционально |
| L1 — Реактивный / периферийный | 10–100 Гц | evernight на SBC; небольшие локальные модели | нет |
| L0 — Управление в реальном времени | 100 Гц–1 кГц | быстрый цикл MCU, локальные блокировки | никогда |

Если LLM отключается, платформа деградирует изящно: либо безопасное
состояние, либо продолжение выполнения уже одобренной траектории. Аппаратные
сторожевые таймеры закрепляют эту семантику — управление никогда не ждёт
сетевого вызова.

## 4. Нулевое доверие, отказ по умолчанию

- Аутентификация и авторизация приходят из
  [kirino](https://github.com/celestia-island/kirino): JWT с короткоживущими
  сессиями, хеширование паролей Argon2id, ограничение частоты входа и движок
  RBAC.
- Регистрация по умолчанию закрыта приглашениями; первый пользователь
  развёртывания становится администратором, после чего самостоятельная
  регистрация блокируется.
- Всё, что явно не разрешено, запрещено. Там, где сервис имеет режим *mock*,
  он по умолчанию выключен и отказывается работать в производственных
  развёртываниях без явного флага.

## 5. Сбои громкие

Тихая деградация рассматривается как ошибка безопасности. Если извлечение из
памяти не сработало, бэкенд недоступен или развёртывание не удалось, ответ
API и UI обязаны сказать об этом явно — никакого фальшивого успеха, никакого
отката к фиктивным данным. Это правило существует, потому что реальные
инциденты показали: невидимые сбои — самые опасные.
