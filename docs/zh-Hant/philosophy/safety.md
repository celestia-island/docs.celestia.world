# 安全原則

工業控制是安全關鍵的：一次失敗可能移動實體設備。因此安全被設計進架構，而不是最後才補。

## 1. 模型永不直接觸碰世界

模型是規劃者，不是致動器。它可以請求完成工作，卻不能親自執行。模型與設備之間隔著沙箱、策略校驗，以及——對不可逆的動作——人。模型無法發明平台未暴露的原語之外的行為。

## 2. 多層安全縱深

每個可能影響實體世界的操作都依序通過完整鏈條：

1. **指令審查** —— 模型被告知要做什麼
2. **沙箱執行** —— 程式碼隔離執行，受策略約束
3. **策略校驗** —— 寫入閘門：操作是否符合策略？
4. **人工確認** —— 不可逆動作的最終決定權
5. **稽核軌跡** —— 一切皆有紀錄，沒有靜默

沒有任何一層信任前一層。跳過任何一層都是缺陷，不是捷徑。

## 3. 混合關鍵性：即時層永不依賴模型

系統按回應時間分層，**越快的一層，越不依賴模型線上**：

| 層 | 做什麼 | LLM 依賴 |
| --- | --- | --- |
| 認知 | 規劃、對話、編排 | 主要消費者 |
| 世界狀態 | 此刻為真的事實，而非被說出的內容 | 可選 |
| 反應 | 機器上的本機反應 | 無 |
| 即時控制 | 連鎖與快環 | 永不 |

模型斷線時平台優雅降級：進入安全態，或繼續執行已核准的軌跡。控制永不等待網路呼叫。

## 4. 零信任，預設拒絕

- 認證與授權來自 [kirino](https://github.com/celestia-island/kirino)，生態的零信任認證層。任何東西都不因位於網路內部而被信任。
- 註冊預設邀請制；部署的首個使用者成為管理員，此後自助註冊上鎖。
- 未被明確允許即為拒絕。凡服務帶有 *mock* 模式，mock 預設關閉，未顯式傳參時拒絕在產線部署中執行。

## 5. 失敗必須響亮

靜默降級被當作安全缺陷。記憶召回失敗、後端不可達、部署失敗——API 回應與 UI 必須顯式說明；不允許假成功，不允許回退到假資料。這條規則源於真實事故：看不見的失敗才是危險的失敗。
