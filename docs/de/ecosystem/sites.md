# Sites & Verantwortlichkeiten

Dokumentation folgt in diesem Ökosystem einer Regel: **der Hub erklärt das
Warum und das Wo; jede Projektsite erklärt das Wie.** Das hält den Hub klein
und die Projektsites maßgeblich.

## Wer besitzt was

| Site | Besitzt | Inhalt |
| --- | --- | --- |
| [docs.celestia.world](https://docs.celestia.world) | das Ökosystem | Philosophie, Ökosystem-Karte, Erste Schritte, Governance (Lizenz, CLA, CoC, Sicherheit, Mitwirken) |
| `<name>.docs.celestia.world` | jedes Projekt | Leitfäden, Architektur, Designs, Referenzen — aus dem eigenen Repository des Projekts erstellt |
| [celestia-island.github.io](https://celestia-island.github.io) | die Organisation | Präsenz, Links, Marken-Assets |
| [e.celestia.world](https://e.celestia.world) | das öffentliche Gesicht | Landingpage, Preise, Blog, Call-to-Action |
| [dev.celestia.world](https://dev.celestia.world) | Entwickler | Entwicklerportal und Status |

## Die eine Regel: keine Duplikate

- Der Hub **kopiert nie** Projektdokumentation. Wenn ein Thema zu einem Projekt
  gehört (wie ein Protokoll funktioniert, wie ein Dienst konfiguriert wird),
  verlinkt der Hub auf die Projektsite, statt es zusammenzufassen.
- Projektsites **dürfen zurück** auf den Hub verlinken, für Philosophie und
  projektübergreifenden Kontext.
- Wenn ein Projekt groß genug ist, um seine eigene Dokumentation zu pflegen,
  reduziert der Hub seine Abdeckung auf einen Karteneintrag plus Links.

## Wie die Sites entstehen

Jede Doku-Site (diese eingeschlossen) wird mit
[lagrange](https://github.com/celestia-island/lagrange) aus Markdown im
Repository des Projekts erstellt, mit einem gemeinsamen Sprachumschalter. Die
Inhalte werden auf Englisch verfasst; Übersetzungen folgen derselben Struktur
und werden gekennzeichnet, wenn sie unvollständig sind.
