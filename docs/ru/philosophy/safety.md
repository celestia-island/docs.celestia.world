# Принципы безопасности

Промышленное управление критично к безопасности: отказ может привести в
движение физическое оборудование. Поэтому безопасность заложена в архитектуру,
а не добавлена в конце.

## 1. Модель никогда не касается мира напрямую

Модель — это планировщик, а не исполнительный механизм. Она может попросить
выполнить работу; выполнить её она не может. Между моделью и оборудованием
стоят песочница, проверка политик и — для необратимых действий — человек.
Модель не может изобрести поведение вне примитивов, которые предоставляет
платформа.

## 2. Многослойная глубина защиты

Каждая операция, способная повлиять на физический мир, проходит всю цепочку
по порядку:

1. **Проверка инструкции** — что модели велели сделать
2. **Выполнение в песочнице** — код работает изолированно, с ограничениями политик
3. **Проверка политик** — шлюз записи: соответствует ли операция политике?
4. **Подтверждение человеком** — последнее слово для необратимых действий
5. **Журнал аудита** — записывается всё, ничто не остаётся безмолвным

Ни один слой не доверяет предыдущему. Пропуск слоя — это дефект, а не ярлык.

## 3. Смешанная критичность: реальное время никогда не зависит от модели

Система разделена по времени отклика, и **чем быстрее слой, тем меньше он
зависит от того, что модель онлайн**:

| Слой | Что он делает | Зависимость от LLM |
| --- | --- | --- |
| Познание | планирование, беседа, оркестрация | основной потребитель |
| Состояние мира | что верно прямо сейчас, а не что было сказано | опционально |
| Реактивный | локальные реакции на самой машине | отсутствует |
| Управление в реальном времени | блокировки и быстрый цикл | никогда |

Если модель уходит в офлайн, платформа деградирует изящно: либо безопасное
состояние, либо продолжение выполнения уже одобренной траектории. Управление
никогда не ждёт сетевого вызова.

## 4. Нулевое доверие, отказ по умолчанию

- Аутентификация и авторизация приходят из
  [kirino](https://github.com/celestia-island/kirino), слоя аутентификации
  экосистемы с нулевым доверием. Ничто не пользуется доверием только потому,
  что находится внутри сети.
- Регистрация по умолчанию закрыта приглашениями; первый пользователь
  развёртывания становится администратором, после чего самостоятельная
  регистрация блокируется.
- Всё, что явно не разрешено, запрещено. Там, где у сервиса есть *мок*-режим,
  мок-режим по умолчанию выключен и отказывается работать в продакшн-
  развёртываниях без явного флага.

## 5. Отказы громкие

Безмолвная деградация считается ошибкой безопасности. Если извлечение из
памяти не удалось, бэкенд недостижим или развёртывание провалилось, ответ API и
UI должны сказать об этом явно — никакого фальшивого успеха, никакого отката к
подставным данным. Это правило существует потому, что реальные инциденты
показали: опасны именно невидимые отказы.
