# 安全原则

工业控制是安全关键的：一次失败可能移动物理设备。因此安全被设计进架构，而不是最后才补。

## 1. 模型永不直接触碰世界

模型是规划者，不是执行器。它可以请求完成工作，但不能亲自执行。模型与设备之间隔着沙箱、策略校验，以及——对不可逆动作——一个人。模型不能发明平台暴露的原语之外的行为。

## 2. 多层安全纵深

每个可能影响物理世界的操作都按序通过完整链条：

1. **指令审查** —— 模型被告知要做什么
2. **沙箱执行** —— 代码隔离运行，受策略约束
3. **策略校验** —— 写阀门：操作是否符合策略？
4. **人工确认** —— 不可逆动作的最终决定权
5. **审计轨迹** —— 一切皆有记录，没有静默

没有一层信任它前面那一层。跳过一层是缺陷，不是捷径。

## 3. 混关键性：实时层永不依赖模型

系统按响应时间分层，且**层越快，对模型在线的依赖越少**：

| 层 | 做什么 | LLM 依赖 |
| --- | --- | --- |
| 认知 | 规划、对话、编排 | 主要消费者 |
| 世界状态 | 此刻何为真，而非谁说了什么 | 可选 |
| 反应 | 机器本身的本地反应 | 无 |
| 实时控制 | 联锁与快环 | 永不 |

模型掉线时平台优雅降级：要么进入安全态，要么继续执行已批准的安全轨迹。控制永不等待网络调用。

## 4. 零信任，默认拒绝

- 认证与授权来自 [kirino](https://github.com/celestia-island/kirino)——生态的零信任认证层。没有任何东西因为它在网络内部而被信任。
- 注册默认邀请制；部署的首个用户成为管理员，此后自助注册上锁。
- 未被明确允许即为拒绝。凡服务带有 *mock* 模式，mock 默认关闭，且未显式传参时拒绝在生产部署中运行。

## 5. 失败必须响亮

静默降级被当作安全缺陷。记忆召回失败、后端不可达、部署失败——API 响应与 UI 必须显式说明：不允许假成功，不允许回退到假数据。这条规则之所以存在，是因为真实事故已经表明：看不见的失败才是危险的失败。
