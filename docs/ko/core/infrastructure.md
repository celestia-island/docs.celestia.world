# 핵심 인프라 — 인증, RPC 및 기반

여러분이 사용하는 모든 플랫폼은 동일한 기반 위에 놓입니다. 이 문서를 한 번만
읽으면 플랫폼 가이드들이 제자리에 끼워집니다: kirino(제로 트러스트 인증 및
RBAC), plana(프로토콜 타입 및 플랫폼 기반 기능), 그리고 hikari(UI 컴포넌트
라이브러리)입니다.

## 인증 및 권한 부여 (kirino)

- **신원**: 비밀번호 해싱, 수명이 짧은 세션 토큰, 로그인 비율 제한 및 계정
  잠금. 알고리즘과 파라미터는 여기가 아니라
  [kirino 자체 문서](https://kirino.docs.celestia.world)에 문서화되어
  있습니다.
- **RBAC**: 권한은 계층적이며 호출자별로 해석됩니다; 역할은 권한을 묶고
  (관리자는 모든 것을 보고, 뷰어는 읽기 전용), 할당은 플랫폼 데이터베이스에
  유지됩니다.
- **위임**: 다른 서비스 뒤에 놓인 서비스는 스스로 아무도 인증하지 않습니다 —
  인증 계층은 항상 상위에 있으며, 호출자 신원은 워크스페이스 격리 목적으로만
  전달됩니다.

## 프로토콜 및 RPC (plana)

- 플랫폼 트래픽은 **JSON-RPC 2.0**이며, 스트리밍은 WebSocket으로,
  요청/응답은 HTTP POST로 전송됩니다. 메서드 이름은 `<Domain>.<Action>`
  형식입니다.
- 와이어 타입은 프로토콜의 단일 진실 공급원이며 plana에 있습니다; 하위
  저장소는 사본을 포크하는 대신 릴리스된 버전을 고정합니다.
- 알림에는 `id`가 없고 스트리밍 청크, 패널 갱신 같은 이벤트를 밀어냅니다;
  요청은 `id`를 가지며 응답이 그것을 그대로 돌려줍니다.
- 상태가 많은 화면은 어디서나 같은 패턴을 따릅니다: 서버가 권위를 가지며,
  클라이언트는 무엇을 보고 있는지 밝히고, 서버는 그 차이를 스트리밍합니다.

## 계량 및 가격 책정 (plana)

사용량은 API key별로 계량되고, 모든 서비스가 공유하는 하나의 표준 표에서
가격이 책정됩니다: 프롬프트 및 완성 토큰, 비용 추정, 할당량 적용은 모든
제품에서 같은 계산입니다.

## UI 컴포넌트 (hikari)

컴포넌트 라이브러리는 모든 웹UI가 쓰는 버튼, 배지, 표, 모달, 확인
대화상자를 제공하여, 화면이 어디에 마운트되든 같은 모습과 동작을 갖게
합니다. 공유 컴포넌트는 저장소마다 다시 구현하는 대신 이곳으로 상류화됩니다.

## 의존성 규칙

- 계층 0: kirino(인증) → 계층 1: plana(프로토콜/기반) → 계층 2: hikari(UI)
  → 계층 3: 서비스(arona, chest, entelecheia, evernight).
- 서비스는 비즈니스 로직만 구현합니다; 공유 능력은 상위에서 옵니다. 저장소 간
  의존성은 git 참조 또는 고정된 태그를 사용하며, 로컬 경로 의존성은 절대 쓰지
  않습니다.
