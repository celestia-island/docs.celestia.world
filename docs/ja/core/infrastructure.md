# コアインフラストラクチャ — 認証、RPC と基盤

あなたが使うすべてのプラットフォームは、同じ基盤の上に載っています。この
ページを一度読んでおけば、プラットフォームガイドの全体像が分かります:
kirino（ゼロトラスト認証と RBAC）、plana（プロトコル型、JSON-RPC
トランスポート、計測、同期エンジン）、hikari（UI コンポーネントライブラリ）です。

## 認証と認可（kirino）

- **アイデンティティ**: Argon2id によるパスワードハッシュ、JWT アクセス/
  リフレッシュトークン（`TokenManager`、`kirino-session`）、ログイン
  レート制限とアカウントロック。
- **RBAC**: 階層的なパーミッション（agent.*、system.*、knowledge.*、…）を
  `GrantResolver` が解決します。ロールはパーミッションを束ねます（admin は
  すべてを見られ、viewer は読み取り専用）。割り当ては Postgres に永続化
  されます。
- **委任**: scepter は chest ゲートウェイが供給する呼び出し元ユーザー ID
  （`X-User-Id` / `user_id`）を信頼し、それをワークスペースの分離のため
  だけに使います —— 認証するレイヤは常に上流です。
- **管理サーフェス**: パネルの管理エンドポイントは専用の
  `ARONA_ADMIN_TOKEN` を要求し、それがなければフェイルクローズドします。

## プロトコルと RPC（plana）

- すべてのプラットフォームトラフィックは **WebSocket 上の JSON-RPC 2.0**
  です（および HTTP POST `/api/rpc` によるリクエスト/レスポンス）。メソッド
  は `<Domain>.<Action>` と名付けられます —— 例: `Sync.MemoryQueryRequest`、
  `Cli.Search`、`Mcp.CallTool`。
- ワイヤ型は plana（`plana-state-sync` / `plana-types`）にあります。
  プロトコルの唯一の真実の情報源であり、下流リポジトリはリリース済み
  タグに固定します。
- 通知（`id` なし）はストリーミングチャンクやパネル更新などのイベントを
  プッシュします。リクエストは `id` を運び、レスポンスでエコーされます。
- 同期エンジン（`plana-sync`）はサーバー権威のステートツリーです。
  クライアントはビューポートを宣言し、サーバーは定期的なフルスナップ
  ショットとともに差分をブロードキャストします。

## 計測と価格設定（plana）

利用量は API キーごとに計測され、正規のテーブル（`plana-llm-provider` の
計測）から価格付けされます。プロンプト/完了トークン、コスト推定、クォータ
執行はサービス間で共有されます。

## UI コンポーネント（hikari）

Vue コンポーネントライブラリ（`@celestia-island/hikari`）は、すべての
WebUI が使うボタン、バッジ、テーブル、モーダル、確認ダイアログを提供
します。プラットフォームページはそれらを plana の UI シェルと組み合わ
せます。共有コンポーネントはリポジトリごとに再実装するのではなく、必ず
ここへアップストリームします。

## 依存関係のルール

- レイヤ 0: kirino（認証）→ レイヤ 1: plana（プロトコル/基盤）→ レイヤ 2:
  hikari（UI）→ レイヤ 3: サービス（arona、chest、entelecheia、evernight）。
- サービスはビジネスロジックのみを実装し、共有機能は上流から来ます。
  クロスリポジトリ依存は git 参照または固定タグを使います —— ローカル
  パス依存は決して使いません。
