# 为 Celestia Island 做贡献

感谢您有兴趣参与贡献！Celestia Island 是一个横跨整个平台的项目家族——kirino（认证）、plana（平台）、hikari（UI）、服务层，以及围绕它们的各个 WebUI 与站点。本指南描述整个项目组共享的贡献政策；单个项目的构建与开发说明位于该项目自己的仓库与文档站点中。

## 贡献政策（请先阅读）

本项目组按混合关键度分层构建——第 0 层（kirino，认证）、第 1 层（plana，平台）、第 2 层（hikari，UI），以及其上的第 3 层服务——因此**正确性、向后兼容性与稳定性高于贡献吞吐量**。请在发起拉取请求之前先阅读本节。

- **高合并门槛，而非公开路线图。** 发起 PR 并不意味着它会被合并。我们有意只接受少量变更，且仅当它们契合架构并通过评审时才会接受。这是刻意的设计，并非怠慢。
- **我们欢迎的内容：** 缺陷报告、聚焦的修复、增量式（非破坏性）特性与协议字段、文档改进，以及在动手写代码之前的设计讨论。
- **我们通常不会合并的内容：** 大规模未经沟通的重写、对共享契约与协议面（例如整个 Entelecheia 平台共享的 JSON-RPC 2.0 协议类型）的破坏性变更、没有先行设计讨论的架构变更、批量"氛围编程"式 PR，以及任何会拉低更低层级的兼容性、稳健性或安全性的内容。
- **核心与外围。** 零信任认证核心、共享平台类型与共享 UI 组件库执行最严格的标准，并由核心团队维护；针对它们的变更提案应从设计讨论开始。
- **必须签署 CLA。** 每一项被接受的贡献都要求签署贡献者许可协议（CLA）。参见 [`CLA.md`](cla.md)。提交必须携带 `Signed-off-by` 行（使用 `git commit -s`）。

> **许可证可以开放，合并门槛不会。** 自 **2030-01-01** 起，本项目组的各个项目将从 BUSL-1.1 转换为 Apache-2.0 或 MIT（由接收者选择）——参见 [`LICENSE`](../../../LICENSE)。这拓宽的是*您可以对代码做什么*，但它**不会**降低评审门槛、不会取消 CLA，也不意味着我们会接受更多 PR。贡献政策在变更日期前后保持不变。

## 安全

请**不要**为安全漏洞发起公开议题。请通过受影响仓库的 GitHub Security Advisories 私下报告，或发送邮件至 <security@celestia.world>。参见 [`SECURITY.md`](security.md)。

## 行为准则

请保持尊重、建设性与包容。我们遵循[贡献者公约行为准则](code-of-conduct.md)。

## 快速上手

选择您想参与的项目，并遵循其 README 与文档站点。Rust 项目使用 `cargo fmt`、`cargo clippy -D warnings` 与 `cargo test` 验证；Web 项目使用 `pnpm lint`、`pnpm build` 与 `pnpm test` 验证。[站点分工](../ecosystem/sites.md)列出了每个项目及其文档所在的位置。

## 拉取请求流程

1. 从仓库的默认分支派生并创建分支。
1. 大型或涉及共享契约的变更，先在议题中讨论。
1. 保持原子提交：每个提交主题为一个 gitmoji 加上一句以句号结尾的英文句子，细节写入提交正文。
1. 推送之前确保项目的各项检查通过。
1. 签署 CLA，并在每个提交中添加 `Signed-off-by`。
1. 回应评审意见；force-push 仅用于变基。

## 许可证与 CLA

本项目组中的项目以 **Business Source License 1.1（BUSL-1.1）** 许可，**变更日期为 2030-01-01**，届时每个项目将转换为接收者从 **Apache-2.0 或 MIT** 中任选其一。对于内部、学术、政府、教育及非商业用途，它们在今天已经等同于 Apache-2.0 或 MIT（参见每个仓库 [`LICENSE`](../../../LICENSE) 中的附加使用授权）。受限的商业用途（托管、转售或以服务形式更换品牌运营）在变更日期之前需要单独的商业许可。

参与贡献即表示您同意您的贡献依照本项目许可证进行授权，并且您将签署 CLA（[`CLA.md`](cla.md)）。CLA 向本项目授予一项宽松许可，**包括改换许可证的权利**，使各项目得以维持 BUSL→Apache/MIT 的路径，并在未来调整其许可安排。
