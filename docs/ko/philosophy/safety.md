# 안전 원칙

산업 제어는 안전 필수(safety-critical)입니다: 실패는 물리적 장비를 움직일 수
있습니다. 따라서 안전은 끝에 덧붙여지는 것이 아니라 아키텍처에 설계되어
있습니다.

## 1. LLM은 세계에 직접 접촉하지 않습니다

[entelecheia](https://github.com/celestia-island/entelecheia)에서 모델은 소수의
프리미티브 도구(`exec`, `write_to_var`)만 볼 수 있습니다. 모든 실제 작업은
에이전트 코드가 에이전트 전반에 걸친 넓은 MCP 도구 표면에 디스패치하는
샌드박스 실행 파이프라인 안에서 일어납니다. 모델은 동작을 창조할 수 없고,
플랫폼이 노출한 프리미티브만 호출할 수 있습니다.

## 2. 다층 안전 깊이

물리적 세계에 영향을 줄 수 있는 모든 작업은 전체 체인을 순서대로
통과합니다:

1. **지침 검토** — 모델이 지시받은 내용
2. **샌드박스 실행** — 코드가 정책 제약과 함께 격리되어 실행됨
3. **정책 검증** — 쓰기 게이트: 작업이 정책과 일치하는가?
4. **인간 확인** — 되돌릴 수 없는 작업에 대한 최종 결정
5. **감사 추적** — 모든 것이 기록되고, 어떤 것도 조용히 지나가지 않음

## 3. 혼합 중요도: 실시간은 절대 LLM에 의존하지 않습니다

시스템은 응답 시간별로 분리되며, **더 빠른 계층은 모델이 온라인 상태인 것에
절대 의존하지 않습니다**:

| 계층 | 주기 | 실행 위치 | LLM 의존성 |
| --- | --- | --- | --- |
| L3 — 인지 | 초–분 | arona, shittim-chest, entelecheia (Linux) | 주요 소비자 |
| L2 — 세계 모델 | 10–50 Hz | 플랫폼 서비스 | 선택적 |
| L1 — 반응형 / 엣지 | 10–100 Hz | SBC의 evernight; 소형 로컬 모델 | 없음 |
| L0 — 실시간 제어 | 100 Hz–1 kHz | MCU 고속 루프, 로컬 인터록 | 절대 없음 |

LLM이 오프라인이 되면 플랫폼은 우아하게 저하됩니다: 안전 상태로 가거나,
이미 승인된 궤적의 실행을 계속합니다. 하드웨어 워치독이 이 의미론을
고정합니다 — 제어는 네트워크 호출을 기다리지 않습니다.

## 4. 제로 트러스트, 실패 시 폐쇄

- 인증과 권한 부여는 [kirino](https://github.com/celestia-island/kirino)에서
  옵니다: 수명이 짧은 세션을 가진 JWT, Argon2id 비밀번호 해싱, 로그인 비율
  제한, RBAC 엔진.
- 등록은 기본적으로 초대 게이트가 있습니다; 배포의 첫 번째 사용자가
  관리자가 되고, 그 후 자체 등록은 잠깁니다.
- 명시적으로 허용되지 않은 것은 모두 거부됩니다. 서비스에 *mock* 모드가
  있는 경우, mock 모드는 기본적으로 꺼져 있고 명시적인 플래그 없이는
  프로덕션 배포에서 실행을 거부합니다.

## 5. 실패는 시끄럽습니다

조용한 성능 저하는 안전 버그로 취급됩니다. 메모리 회상이 실패하거나,
백엔드에 도달할 수 없거나, 배포가 실패하면 API 응답과 UI가 명시적으로
말해야 합니다 — 가짜 성공도, 가짜 데이터로의 폴백도 없습니다. 이 규칙은
보이지 않는 실패가 위험한 실패임을 실제 사고가 보여주었기 때문에
존재합니다.
