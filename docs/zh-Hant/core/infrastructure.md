# 核心基礎架構 —— 認證、RPC 與基礎

你使用的每個平台都建立在同一套基礎之上。這一頁讀一遍，各平台指南便能豁然貫通：kirino（零信任認證與 RBAC）、plana（協定型別與平台設施）與 hikari（UI 元件庫）。

## 認證與授權（kirino）

- **身分**：密碼雜湊、短生命週期的工作階段權杖、登入限流與帳戶鎖定。演算法及其參數記載於 [kirino 自己的文件](https://kirino.docs.celestia.world)，不在這裡。
- **RBAC**：權限具階層性並按呼叫者解析；角色捆綁權限（admin 全見，viewer 唯讀）。指派持久化於平台資料庫。
- **委派**：位於另一層之後的服務自身不認證任何人——認證層永遠在上游，呼叫者身分只被傳遞用於工作區隔離。

## 協定與 RPC（plana）

- 平台流量是 **JSON-RPC 2.0**，串流走 WebSocket，請求/回應走 HTTP POST。方法命名為 `<Domain>.<Action>`。
- 線路型別是協定的單一事實來源，位於 plana；下游倉庫釘住已發布的版本，而不是分叉一份副本。
- 通知沒有 `id`，推送串流區塊與面板更新等事件；請求帶有 `id`，並在回應中原樣回顯。
- 重狀態的介面處處遵循同一模式：伺服端權威，用戶端宣告自己正在看什麼，伺服端串流差異。

## 計量與定價（plana）

用量按 API 金鑰計量，並依一份由所有服務共享的規範表定價：prompt 與 completion token、成本估算與配額強制執行，在每個產品中都是同一套計算。

## UI 元件（hikari）

元件庫提供每個 WebUI 都在使用的按鈕、徽章、表格、模態框與確認對話框，因此無論裝載在哪裡，畫面外觀與行為都一致。共享元件必須上游化到這裡，而不是在各倉庫重複實作。

## 依賴規則

- 第 0 層：kirino（認證）→ 第 1 層：plana（協定/基礎）→ 第 2 層：hikari（UI）→ 第 3 層：服務（arona、chest、entelecheia、evernight）。
- 服務僅實作業務邏輯；共享能力來自上游。跨倉依賴使用 git reference 或釘版 tag——絕不使用本機 path 依賴。
