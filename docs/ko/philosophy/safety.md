# 안전 원칙

산업 제어는 안전 필수입니다: 실패 하나가 물리 장비를 움직일 수 있습니다.
따라서 안전은 끝에 얹히는 것이 아니라 아키텍처에 설계되어 들어갑니다.

## 1. 모델은 세계를 직접 건드리지 않는다

모델은 액추에이터가 아니라 플래너입니다. 어떤 작업을 하도록 요청할 수는
있지만 직접 수행할 수는 없습니다. 모델과 장비 사이에는 샌드박스, 정책
검사, 그리고 되돌릴 수 없는 동작에 한해 사람이 있습니다. 모델은 플랫폼이
노출하는 프리미티브 밖의 동작을 지어낼 수 없습니다.

## 2. 다층 안전 깊이

물리 세계에 영향을 줄 수 있는 모든 작업은 정해진 순서로 전체 체인을
통과합니다:

1. **지시 검토** — 모델이 무엇을 하라고 들었는지
2. **샌드박스 실행** — 코드는 정책 제약 아래 격리되어 실행됩니다
3. **정책 검증** — 쓰기 게이트: 이 작업이 정책에 맞는가?
4. **사람 확인** — 되돌릴 수 없는 동작에 대한 최종 결정
5. **감사 기록** — 모든 것이 기록되며, 조용히 넘어가는 것은 없습니다

어떤 계층도 앞의 계층을 신뢰하지 않습니다. 하나를 건너뛰는 것은 지름길이
아니라 결함입니다.

## 3. 혼합 임계도: 실시간은 모델에 의존하지 않는다

시스템은 응답 시간으로 분할되며, **계층이 빠를수록 모델이 온라인일 것에
대한 의존이 적습니다**:

| 계층 | 하는 일 | LLM 의존 |
| --- | --- | --- |
| 인지 | 계획, 대화, 오케스트레이션 | 주 소비자 |
| 세계 상태 | 말해진 것이 아니라 지금 참인 것 | 선택적 |
| 반응 | 기계 자체에서의 로컬 반응 | 없음 |
| 실시간 제어 | 인터록과 빠른 루프 | 절대 없음 |

모델이 오프라인이 되면 플랫폼은 우아하게 저하됩니다: 안전 상태로 가거나,
이미 승인된 궤적을 계속 실행합니다. 제어는 절대 네트워크 호출을
기다리지 않습니다.

## 4. 제로 트러스트, 실패 시 폐쇄

- 인증과 권한 부여는 생태계의 제로 트러스트 인증 계층인
  [kirino](https://github.com/celestia-island/kirino)에서 옵니다. 네트워크
  안에 있다는 이유만으로 신뢰되는 것은 없습니다.
- 등록은 기본적으로 초대 게이트가 있습니다; 배포의 첫 번째 사용자가
  관리자가 되고, 그 후 자체 등록은 잠깁니다.
- 명시적으로 허용되지 않은 것은 모두 거부됩니다. 서비스에 *목(mock)* 모드가
  있는 경우, 목 모드는 기본적으로 꺼져 있고 명시적인 플래그 없이는 운영
  배포에서 실행을 거부합니다.

## 5. 실패는 시끄럽다

조용한 성능 저하는 안전 버그로 취급합니다. 메모리 회수가 실패하거나,
백엔드에 도달할 수 없거나, 배포가 실패하면 API 응답과 UI가 그것을
명시적으로 알려야 합니다 — 가짜 성공도, 꾸며낸 데이터로의 폴백도 없습니다.
이 규칙이 있는 이유는 실제 사고를 통해 보이지 않는 실패가 가장 위험하다는
것이 드러났기 때문입니다.
