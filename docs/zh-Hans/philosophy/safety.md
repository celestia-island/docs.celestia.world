# 安全原则

工业控制是安全关键的：一次失败可能移动物理设备。因此安全被设计进架构，而不是最后才补。

## 1. LLM 永不直接触碰世界

在 [entelecheia](https://github.com/celestia-island/entelecheia) 中，模型只看到少量原语工具（`exec`、`write_to_var`）。所有真实工作在沙箱化执行管线内发生，智能体代码在其中通过 ES 模块派发到跨智能体的大量 MCP 工具。模型不能发明行为；它只能调用平台暴露的原语。

## 2. 多层安全纵深

每个可能影响物理世界的操作都按序通过完整链条：

1. **指令审查** —— 模型被告知要做什么
2. **沙箱执行** —— 代码隔离运行，受策略约束
3. **策略校验** —— 写阀门：操作是否符合策略？
4. **人工确认** —— 不可逆动作的最终决定权
5. **审计轨迹** —— 一切皆有记录，没有静默

## 3. 混关键性：实时层永不依赖 LLM

系统按响应时间分层，**越快越不依赖模型在线**：

| 层 | 节奏 | 运行于 | LLM 依赖 |
| --- | --- | --- | --- |
| L3 — 认知 | 秒~分钟 | arona、shittim-chest、entelecheia（Linux） | 主要消费者 |
| L2 — 世界模型 | 10–50 Hz | 平台服务 | 可选 |
| L1 — 反应/边缘 | 10–100 Hz | evernight on SBC；本地小模型 | 无 |
| L0 — 实时控制 | 100 Hz–1 kHz | MCU 快环、本地联锁 | 永不 |

LLM 掉线时平台优雅降级：进入安全态，或继续执行已批准的安全轨迹。硬件看门狗锚定这一语义——控制永不等待网络调用。

## 4. 零信任，默认拒绝

- 认证与授权来自 [kirino](https://github.com/celestia-island/kirino)：短生命周期 JWT 会话、Argon2id 密码哈希、登录限流与 RBAC 引擎。
- 注册默认邀请制；部署首个用户自动成为管理员，此后自助注册上锁。
- 未被明确允许即为拒绝。凡服务带有 *mock* 模式，mock 默认关闭，未显式传参时拒绝在产线部署中运行。

## 5. 失败必须响亮

静默降级被当作安全缺陷。记忆召回失败、后端不可达、部署失败——API 响应与 UI 必须显式说明；不允许假成功，不允许回退到假数据。这条规则源于真实事故：看不见的失败才是危险的失败。
