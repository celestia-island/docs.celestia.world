# 왜 celestia-island인가

celestia-island는 하나의 루프를 닫기 위해 존재합니다: **사용자가 플랫폼을
발견하는 순간부터 실제 산업 장비를 제어했음을 검증하는 순간까지 — 중간의
모든 것이 도구의 더미가 아니라 하나의 시스템으로 동작하는 것.**

## 문제

두 세계는 좀처럼 대화하지 않습니다:

- **AI 플랫폼**(채팅, 에이전트, 모델 배포)은 관대한 세계를 전제로 합니다:
  지연은 UX 문제이고, 실패한 추론은 재시도되며, 물리적으로 움직이는 것은
  없습니다.
- **산업 제어**(프로토콜, 센서, 액추에이터)는 엄격한 세계를 전제로 합니다:
  데드라인, 인터록, 감사 기록, 그리고 소프트웨어가 실패할 때의 안전 상태.

두 세계를 잇는다는 것은 챗봇을 SCADA 시스템에 볼트로 붙이는 일을 거부하는
것입니다. 인증, 모델 배포, 에이전트 오케스트레이션, 프로토콜 브로커링,
감독까지 전체 경로를 모든 단계마다 안전 이야기를 갖춘 하나의 계층화된
시스템으로 설계하는 일입니다.

## 약속: 하나의 폐쇄 루프

제품은 루프입니다. 채팅 앱도, 제어 브로커도, 문서 사이트도 아닌 **루프**:

> 발견 → 설치 → 인증 → 모델 배포 → 채팅 및 에이전트 실행 →
> 산업 장비 제어 → 검증 및 지원

모든 프로젝트는 이 루프의 한 구간을 신뢰할 수 있게 만들기 위해
존재합니다. 루프가 어디서든 끊긴다면 플랫폼은 완성되지 않은 것입니다.
[폐쇄 루프](./closed-loop.md) 페이지가 각 구간을 프로젝트에 대응시킵니다.

## 원칙: 두 번 구현하지 않는다

서른 개가 넘는 저장소에서 질서는 하나의 규칙에서 나옵니다: **일반적인
능력은 상위에서 한 번만 만들고, 서비스는 비즈니스 로직만 구현합니다.**
인증 프리미티브는 [kirino](../ecosystem/projects.md)에서, 플랫폼 기반 기능은
[plana](../ecosystem/projects.md)에서, UI 컴포넌트는
[hikari](../ecosystem/projects.md)에서 옵니다. 상위 기능을 다시 구현하는
서비스는 성과가 아니라 버그입니다. 전체 원칙은
[계층 구조](./layered-architecture.md)를 참고하세요.

## 전망: 로컬 자율성

왕복은 공짜가 아닙니다. 링크가 길거나, 혼잡하거나, 아예 없을 때 어딘가
멀리 있는 사람에게 의존할 수는 없습니다 — 기계는 로컬에서, 안전하게,
예측 가능하게 판단해야 합니다.

오늘 산업 제어를 위해 만드는 모습 — 에이전트를 오케스트레이션하는 결정
레이어, *지금* 무슨 일이 일어나는지 아는 세계 모델, 그리고 *아니오*라고
말하는 안전 게이트 — 는 왕복이 더 이상 공짜가 아니게 되는 순간 어떤 배포든
필요하게 되는 모습입니다. 그 미래를 위해 다른 시스템을 만드는 것이
아니라, 이미 옳은 모습이 되도록 이 시스템을 만드는 것입니다.
[내러티브 & 지평](./narrative.md)을 참고하세요.
