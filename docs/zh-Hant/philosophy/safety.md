# 安全原則

工業控制是安全關鍵的：一次失敗可能移動實體設備。因此安全被設計進架構，而不是最後才補。

## 1. LLM 永不直接觸碰世界

在 [entelecheia](https://github.com/celestia-island/entelecheia) 中，模型只看到少量原語工具（`exec`、`write_to_var`）。所有真實工作在沙箱化執行管線內發生，智能體程式碼在其中透過 ES 模組分派到橫跨智能體的大量 MCP 工具。模型不能發明行為；它只能呼叫平台暴露的原語。

## 2. 多層安全縱深

每個可能影響實體世界的操作都依序通過完整鏈條：

1. **指令審查** —— 模型被告知要做什麼
2. **沙箱執行** —— 程式碼隔離執行，受策略約束
3. **策略校驗** —— 寫入閥門：操作是否符合策略？
4. **人工確認** —— 不可逆動作的最終決定權
5. **稽核軌跡** —— 一切皆有紀錄，沒有靜默

## 3. 混合關鍵性：即時層永不依賴 LLM

系統按回應時間分層，**越快越不依賴模型線上**：

| 層 | 節奏 | 執行於 | LLM 依賴 |
| --- | --- | --- | --- |
| L3 — 認知 | 秒~分鐘 | arona、shittim-chest、entelecheia（Linux） | 主要消費者 |
| L2 — 世界模型 | 10–50 Hz | 平台服務 | 可選 |
| L1 — 反應/邊緣 | 10–100 Hz | evernight on SBC；本機小模型 | 無 |
| L0 — 即時控制 | 100 Hz–1 kHz | MCU 快環、本機連鎖 | 永不 |

LLM 斷線時平台優雅降級：進入安全態，或繼續執行已核准的安全軌跡。硬體看門狗錨定此語意——控制永不等待網路呼叫。

## 4. 零信任，預設拒絕

- 認證與授權來自 [kirino](https://github.com/celestia-island/kirino)：短生命週期 JWT 工作階段、Argon2id 密碼雜湊、登入限流與 RBAC 引擎。
- 註冊預設邀請制；部署首個使用者自動成為管理員，此後自助註冊上鎖。
- 未被明確允許即為拒絕。凡服務帶有 *mock* 模式，mock 預設關閉，未顯式傳參時拒絕在產線部署中執行。

## 5. 失敗必須響亮

靜默降級被當作安全缺陷。記憶召回失敗、後端不可達、部署失敗——API 回應與 UI 必須顯式說明；不允許假成功，不允許回退到假資料。這條規則源於真實事故：看不見的失敗才是危險的失敗。
